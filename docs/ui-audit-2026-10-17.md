# 3D planner and movie functional audit — 2026-10-17

Scope: usability, correctness, responsiveness, and one complete two-player turn.
Visual polish is tracked separately in [the visual handoff](visual-handoff-2026-10-17.md).
Rendering fidelity is a user requirement. Cinematic remains the default and keeps
native render resolution (existing DPR cap of 2), geometry, materials, 4x geometry
antialiasing, 2048 shadow maps, AO, bloom, and continuous robot/overlay animation.
After the initial audit, the user authorized a lower-detail option if optimization
alone could not make the older machine responsive. The explicit Balanced and
Performance choices described below are opt-in; the default is not silently reduced.

## Full-fidelity rendering work

Ordinary hover now stays local to the 3D board, so it does not rerender the squad
rail and every timeline. The GPU marker updates immediately; active aiming still
updates its firing controls. Explicit Move now accepts occupied tiles instead
of selecting the occupying robot, with visible Cancel and Escape paths.

A final fallback check also found the 2D viewport capturing toolbar pointers,
which swallowed the button click to return to 3D. Toolbar pointers now bypass
the canvas pan/pinch handler.

- Repeated rigid leg/foot pieces use instancing. Source joint transforms still
  drive every instance; the underlying geometry and materials are unchanged.
- Shadow maps refresh once every rendered frame, then the AO normal pass reuses
  them. Previously the same shadow scene was rendered twice per frame.
- Geometry is still rendered with 4x MSAA. Resolve it once before the full-screen
  AO/bloom/vignette/output image passes, which do not need multisampled quads.
- Disable drawing-buffer preservation outside explicit capture mode.
- Bound queued GPU work with a zero-timeout WebGL fence poll. A busy GPU yields
  to input; the next submitted frame uses the newest cursor/camera state. This
  removes stale-frame backlog without changing the rendered image.
- Warm the cursor material during asynchronous shader compilation, release the
  WebGL capability-probe context, and omit unused postprocessing depth buffers.
- `?profile=1` exposes frame timing, CPU submission timing, GPU identity, total
  draw calls, and submitted triangles on the canvas for local diagnosis.
- `?gpuProfile=1` optionally measures individual GPU passes. Keep it separate
  from frame-rate measurements because GPU queries can perturb frame pacing.

The final frame of the test movie originally submitted about 1,290 draw calls.
Instancing reduced that to 630 with the same 2,195,107 submitted triangles.
Removing the redundant shadow pass reduced it to about 494 calls and 1,783,939
submitted triangles; the lower triangle count is duplicate-work removal, not
model simplification. The explicit MSAA resolve adds one full-screen draw.

Frame timing is hardware/viewport/load dependent. With one test scene active,
the full-quality 898×561 movie canvas measured approximately 30 ms median and
38 ms p95 on Intel Iris Xe during the audit. Two simultaneously rendering test
tabs were substantially slower. Large 1968×1404 planner rendering remains
GPU-heavy (roughly 80–100 ms median in several full-size samples); do not
describe these changes as a universal 60 FPS guarantee. Optional GPU pass
timing identified scene rendering and AO as the dominant remaining costs.
These are development-browser observations, not a controlled production benchmark.

## Explicit graphics settings and final input evidence

The planner menu and movie toolbar share a persisted **Graphics** selector.
Changing it preserves the draft, movie position, and camera. It remains reachable
at 1024×768; its select target is 44 CSS pixels tall. The preferences are local
presentation settings and never change gameplay or server orders.

| Setting             | Image pixel budget       | AO resolution             | Models, materials, lights, shadows, animation, 4x MSAA |
| ------------------- | ------------------------ | ------------------------- | ------------------------------------------------------ |
| Cinematic (default) | Native, DPR capped at 2  | Full                      | Unchanged                                              |
| Balanced            | Up to 1.5 million pixels | Half the image dimensions | Unchanged                                              |
| Performance         | Up to 0.9 million pixels | Half the image dimensions | Unchanged                                              |

Small canvases retain their native pixels when already below the budget.
Before adding the choice, the audit removed repeated pathfinding, overlay
rebuilds, identical rig updates, excessive draw calls, repeated shadows, redundant
MSAA image passes, and resource leaks. A static-shadow-cache experiment removed
another 347k submitted triangles but did not show a clear frame-time benefit;
it was removed rather than retaining complexity without demonstrated value.

Final single-scene observation on Intel Iris Xe, 1968×1404 CSS planner:
Performance rendered at 1123×801, approximately **36 ms median / 37 ms p95**
per submitted frame in a settled sample. Browser Event Timing measured **40 ms**
from keyboard input through its next paint (about 0.5 ms input delay and 4.1 ms
handler time). The separate cursor-to-GPU-fence diagnostic measured **51–80 ms**
until the updated cursor's GPU work completed. It is not a photon/display-latency
measurement. Full-quality native rendering remains GPU-heavy; the explicit
Performance choice is the practical setting for smooth interaction on this machine.

## Manual two-player exercise

Local room `TELDNY`, match `MdUh8hWvFD`, Audit Red and Audit Blue. Independent
participant identities used `localhost:3000` and `127.0.0.1:3000`. Standard
Survival, Melee formation, Rubble Two, Floodlit theme.

1. Create/join, ready both participants, and start the match.
2. Deploy all eight robots. Exercise legal/blocked deployment and movement;
   face direction, posture, Aim & Fire, repeated shots, Scan & Fire, Missile,
   Rifle, Grenade, and Zap controls. Add/remove a Time Bomb draft and inspect
   the over-budget indication. Exercise timeline details, tail removal, undo,
   redo, keyboard tile choice, and rehearsal.
3. Save and lock Red; verify Red is locked while Blue is still planning.
4. Save and lock Blue; both receive their authorized Turn 1 movies.
5. Play both movies through tick 900. Exercise replay/restart, speed changes,
   stepping, scrub-to-start, camera modes, and reload recovery. The turn contains
   movement, firing, damage, contact changes, and destruction, not just idle time.
6. Acknowledge Blue independently, then Red. Both enter Turn 2. Red has four
   living robots and 408 total HP; Blue has one living Missile robot at 100 HP.
7. At 1024×768, verify all heading buttons, keyboard aiming, shot confirmation,
   special-action confirmation, timeline deletion and undo/redo. Add/remove a
   Self Destruct draft without submitting it. Switch Scan & Fire to Grenade,
   set its duration to two seconds, and confirm its timeline entry. Reload
   restores the Turn 2 draft.
8. With the final queue/cursor/graphics changes, complete another turn. Red
   programs direction, movement (including an occupied destination), and Rifle
   scan; Blue programs Grenade and Missile scan. Both save and lock, both movies
   play to tick 900, and both independently acknowledge and enter Turn 3. The
   turn includes direct fire, blasts, and two Red robot destructions. Blue's
   surviving Missile has 61 HP. Graphics selection persists from planner to
   movie and back; changing it at tick 900 keeps that movie position.

## Verification and limits

The final checks passed: 63 Vitest files (614 tests passed, one skipped),
TypeScript, ESLint, repository formatting, and a production Next.js build.
One scenario CLI test exceeded its five-second timeout during a run competing
with other checks; the complete suite passed when rerun on its own.
Focused regression tests cover hover
reachability versus exact pathfinding, instance transform/material preservation,
and disposal without destroying shared model resources. The retained automated
Playwright suite was not run or re-enabled.

After the final rendering changes, the demo movie also played to its last tick
and switched from 3D to 2D and back without the previous initialization crash.

This audit does not close Phase 12.2. Physical iPad Safari/touch, the four-player
match, server-restart acceptance, and deployed/two-network acceptance remain
separate gates. Viewport testing here used desktop Chromium mouse/keyboard;
it must not be reported as physical-iPad evidence.
